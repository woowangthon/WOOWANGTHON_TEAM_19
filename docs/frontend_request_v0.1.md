# 재하 님께 — 프론트 v0.5를 서버에 붙이기 위한 요청 (2026-11-11, 성호)

v0.5를 받아서 화면을 직접 눌러 보고(360×640, 390×844), 서버에 붙여 봤습니다. 화면 자체는 잘 돌아갑니다. 아래는 **서버에 붙이려면 고쳐야 하는 것**과 **눌러 보다가 찾은 문제**입니다. 디자인(색·글꼴·배치)은 건드리지 않았고 의견도 적지 않았습니다.

- 급한 순서대로 1 → 2 → 3입니다. 프리즈(11-12 22:00) 전에 1과 2가 되면 시연 대본을 화면으로 끝까지 갈 수 있습니다.
- 서버 응답 모양의 정본은 `docs/api_contract_v0.1.md`의 「compat」 절입니다. v0.5의 `types.ts` 모양에 맞춰 서버를 만들었기 때문에 경로 이름은 거의 그대로 쓰시면 됩니다.
- 회의에서 같이 정해야 하는 것은 맨 아래 5절에 따로 모았습니다. 그건 정해진 뒤에 고치면 됩니다.

## 0. 서버에 붙이는 법

```
VITE_API_MODE=http
VITE_API_BASE=<백엔드 주소>/api/v1/compat
```

- 백엔드 주소는 배포되면 알려 드리겠습니다. 로컬에서는 `http://localhost:8000`입니다(`cd backend && uv run uvicorn app.main:app`).
- `http://localhost:5173`(vite 기본 주소)은 서버가 이미 허용해 두었습니다. 배포 주소가 정해지면 알려 주세요. 서버에 등록해야 화면에서 호출이 됩니다.

## 1. 꼭 고쳐야 하는 것 (이게 없으면 시연이 깨집니다)

### 1-1. 풀기 화면이 나눗셈을 뺄셈으로 그립니다
- **지금**: 서버 문제는 분수 나눗셈인데 `3/4 ÷ 2`가 `3/4 − 2/1`로 보입니다. 문제 문장도 안 나옵니다.
- **위치**: `src/screens/student/Solve.tsx` 149줄 근처(`p.op === '+' ? '+' : '−'`), `src/types.ts`의 `ProblemView`.
- **고칠 것**: 기호는 서버가 준 `op`를 그대로 그립니다(`÷`가 옵니다). 서버가 문제 문장을 `text`로 같이 보내니 식 위에 보여 주세요. 문장제 문제가 절반쯤이라 문장이 꼭 보여야 합니다.

### 1-2. 어떤 문제에서는 화면 전체가 하얗게 됩니다
- **지금**: `(1 + 3/4) ÷ 2/3`처럼 식을 두 분수로 나눌 수 없는 문제는 서버가 `left`·`right`를 `null`로 보냅니다. 그때 `src/components/Fraction.tsx` 6줄에서 오류가 나고 화면이 비어 버립니다.
- **고칠 것**: `left`·`right`가 없으면 식은 그리지 않고 문장만 보여 주세요. 그리고 화면 하나가 깨져도 전체가 하얗게 되지 않도록 오류 경계(error boundary)를 하나 넣어 주세요.

### 1-3. 서버 요청에 「누구인지」가 빠져 있습니다
- **지금**: 서버는 요청마다 헤더 두 개로 역할을 확인합니다. 없으면 401입니다.
- **위치**: `src/api/http.ts`의 `call()`.
- **고칠 것**: 로그인한 계정의 역할에 따라 아래 헤더를 붙입니다.

| 화면 | `X-Demo-Role` | `X-Demo-Actor` |
|---|---|---|
| 학생 | `child` | `demo-child-minsu` |
| 보호자 | `guardian` | `demo-guardian-minsu` |
| 학습지도자 | `instructor` | `demo-instructor` |

- 서버의 데모 아이 이름은 체험 계정과 같은 「지우」입니다(11-11 통일). 내부 id는 그대로 `demo-child-minsu` 등입니다. 학습지도자 결과 mock의 「김지우」만 다르게 남아 있습니다.
- 오류 문구: 서버는 `{code, message, request_id}`로 답합니다(compat 경로는 `detail`도 같이 줍니다). `j.message ?? j.detail`로 읽어 주세요.

### 1-4. 일부 함수만 서버로 보내기
- **지금**: `VITE_API_MODE=http`면 모든 함수가 서버로 갑니다. 서버에는 로그인·학원·씨앗·상점이 없어서 로그인 화면에서 멈춥니다.
- **위치**: `src/api/index.ts`.
- **고칠 것**: 아래 함수만 `httpApi`로 보내고 나머지는 지금처럼 `mockApi`를 씁니다.
  - 학생: `getStudentHome`, `acceptPromise`, `getMentor`, `saveMentor`, `getActiveSession`, `startSession`, `getProblem`, `submitAnswer`, `requestHint`, `showSolution`, `afterStudy`, `getChat`, `sendChat`, `endChat`, `getWrap`, `submitWrap`
  - 보호자: `getGuardianToday`, `getAlerts`
  - 학습지도자: `getTeacherToday`, `assignTask`, `getMemo`, `saveMemo`, `createDraft`, `updateDraft`, `approveDraft`, `getTeacherAlerts`
- 캐릭터 그림(`animal`)은 서버에 저장 칸이 없어서 `getMentor`가 `null`로 돌려줍니다. 그림은 지금처럼 화면 쪽에 저장해 주세요.

## 2. 시연 대본을 끝까지 가려면 필요한 것

### 2-1. 수다: 끊어 보내기
아이는 "음…", "3/8?", "맞아?"처럼 끊어서 보냅니다. 그래서 「보내는 동안 입력을 막는다」는 규칙을 바꿨습니다(성호 11-11, 회의에서 확인할 것).

- **위치**: `src/screens/student/Chat.tsx`, `src/api/http.ts`, `src/api/client.ts`.
- **고칠 것**
  1. 입력창과 전송 버튼을 막지 않습니다.
  2. 아이가 보낸 말을 모아 두었다가, 마지막 입력 뒤 1.5초가 지나면 한 번에 보냅니다. 본문은 `{ "texts": ["음…", "3/8?", "맞아?"] }`이고 최대 5개입니다(5개가 차면 바로 보냅니다). 기존 `{ "text": "…" }`도 그대로 됩니다.
  3. 응답에 `queued: true`가 오면 앞의 말에 답을 만드는 중이라는 뜻입니다. 「생각 중…」만 유지하고 다시 보내지 않습니다.
  4. 응답에 `pending: true`가 오면 아직 답하지 않은 말이 남았다는 뜻입니다. `POST /sessions/{id}/reply`(본문 없음)를 불러 다음 답을 받습니다. 그 응답도 `pending: true`면 한 번 더 부릅니다(최대 3번이면 충분합니다). `client.ts`에 함수 하나를 추가해야 합니다.
  5. 답을 기다리는 동안 힌트 버튼은 꺼 주세요(누르면 서버가 409로 거절합니다).
- 참고로 테스트할 때 만든 패치가 있습니다. 필요하시면 파일로 보내 드리겠습니다.

### 2-2. 풀기 화면 흐름 맞추기
- 한 세션에 문제는 **1개**입니다(`total: 1`).
- 힌트는 **2개**이고 그다음이 「풀이 같이 보기」입니다. 힌트 점이 3개로 그려져 하나가 남습니다.
- 틀려도 힌트가 자동으로 나오지 않습니다(`autoHint`는 늘 `null`). 힌트는 버튼으로만 엽니다.
- `submitAnswer` 응답에도 `queued`가 올 수 있습니다. `queued: true`면 화면을 넘기지 말고 기다려 주세요.
- 답이 자연수인 문제(3, 2, 8)는 지금 「3 위 1 아래」로 넣어야 정답이 됩니다. 아이가 알 수 있게 안내 한 줄이나 자연수 입력을 넣어 주세요.
- 풀기 20분 카운트다운이 0이 돼도 서버는 단계를 바꾸지 않습니다(서버가 끝내는 것은 수다 10분뿐입니다). 0이 되면 「수다로 갈까?」 같은 선택을 보여 주세요.

### 2-3. 학습지도자 화면
서버에 연결할 수 있게 경로를 만들어 두었습니다. 화면 코드는 거의 그대로 되지만 서버 규칙이 mock과 다른 곳이 있습니다.

- 메모 저장(`saveMemo`) 다음에 초안 만들기(`createDraft`)를 부르는 **지금 순서를 유지**해 주세요. 서버는 메모를 저장하는 순간 초안까지 만들고, `createDraft`는 만들어진 초안을 읽기만 합니다. 메모 저장이 AI를 부르기 때문에 길면 20초까지 걸릴 수 있습니다. 로딩 표시가 필요합니다.
- 초안은 하루에 한 번만 만들어집니다. 같은 날 메모를 다시 저장해도 초안은 바뀌지 않습니다. 문장을 바꾸려면 초안을 직접 고쳐 저장(`updateDraft`)합니다.
- 승인한 뒤에는 고칠 수 없습니다(409). mock처럼 「승인 대기」로 돌아가지 않습니다.
- 「오늘 할 것」은 단원 이름 4개 중에서 고릅니다. 목록은 `getTeacherToday`의 `units`로 옵니다.
- 긴급 알림 탭: 11-15에는 🔴 알림이 보호자에게만 갑니다. 서버는 빈 목록을 돌려줍니다. 탭을 숨겨 주세요.
- 범위(`getUnits`)·결과(`getResults`) 화면은 서버에 없으니 mock 그대로 둡니다.

### 2-4. 리셋 버튼
- **지금**: 「시연 데이터 처음으로」가 브라우저 안의 가짜 데이터만 지웁니다. 서버 데이터는 그대로입니다.
- **고칠 것**: `POST <백엔드 주소>/api/v1/demo/reset`을 부릅니다(compat 경로가 아닙니다). 헤더 `X-Demo-Token`에 시연용 토큰이 필요합니다. **토큰을 코드나 빌드에 넣지 말고** 체험 시트에 입력칸을 두어 그때만 쓰게 해 주세요. 빠른 모드를 켠 상태면 본문에 `{ "timer_scale": 20 }`을 같이 보냅니다. 서버를 리셋한 다음 지금의 가짜 데이터 지우기도 이어서 해 주세요.
- 시간이 없으면 이 버튼은 그대로 두고, 시연할 때 제가 명령어로 리셋하겠습니다.

## 3. 눌러 보다가 찾은 문제

| 화면 | 문제 | 고칠 것 |
|---|---|---|
| 마무리 | 퀴즈 칩에 긴 문장이 오면 화면 밖으로 잘리고, 누르면 본문이 옆으로 밀림 | `.chip`에 `max-width: 100%; white-space: normal` (`styles/global.css` 98줄 근처) |
| 마무리 | 제목이 「선생님께 보낼 한 줄」인데 실제로는 보호자에게 감 | 「보호자께 보낼 한 줄」 |
| 마무리 | 「어려웠던 점」 칩이 비어 있으면(서버는 빈 목록을 줌) 제목만 남음 | 비면 섹션 숨김 |
| 학생 홈 | 「오늘도 해냈어!」와 「오늘 할 것이 아직 없어요」가 같이 나옴 | 끝난 날에는 하나만 |
| 보호자 홈 | 🔴 뒤에도 「아직 오늘 공부 전이에요」 | `solved`가 1 이상이면 다른 문구 |
| 보호자 알림 | 「확인했어요」를 누르면 「괜찮아요」가 켜짐 | 11-15에는 회색 「후속」 버튼만(11-09 결정) |
| 공통 | 서버가 재시작돼 세션이 사라지면 「세션을 찾을 수 없어요」만 뜨고 나갈 길이 없음 | 「처음으로」 버튼 |
| 학습지도자 메모 | 입력칸 4개에 라벨이 연결돼 있지 않아 화면낭독기가 이름을 못 읽음 | `label`과 `id` 연결 |
| 풀기 | 힌트 문장 조사 오류("분모 11는") | mock 문장이라 서버에 붙으면 사라짐 |
| 공통 | 누르는 영역이 44px보다 작음(칩 40, 분자·분모 칸 42, 캐릭터 화살표 36) | 여유 있을 때 |
| 공통 | favicon이 없어 콘솔에 404 | 여유 있을 때 |
| 개발 서버 | `vite.config.ts`의 `host: true`는 같은 와이파이의 다른 기기에서도 접속됨 | 폰으로 볼 때만 켜기 |

잘 되어 있던 것: 가로 스크롤 없음, 전송 중 버튼 비활성(답 확인·시작·보내고 끝내기), 새로고침해도 이어짐, 서버가 꺼졌을 때 오류 문구와 「다시 시도」, 이미지 설명 글.

## 4. 새로 생긴 응답 칸 (알아만 두셔도 됩니다)

- `source`: 그 답을 누가 만들었는지입니다. `live`(AI) / `scripted`(대본) / `fixed`(고정 문장) / `null`(답 없음). `submitAnswer`·`sendChat`·`reply` 응답에 옵니다. 화면에 작은 표시를 달지는 5절에서 같이 정합니다.
- `studyMin`: 이제 수다·마무리 단계에서도 값이 옵니다.
- `needsOnboarding`: 약속에 동의하지 않은 아이면 `true`가 옵니다. `acceptPromise`를 부르면 서버에 저장됩니다.

## 5. 회의에서 같이 정할 것 (정해진 뒤에 고칩니다)

1. **위기 화면 문구**: 화면은 아이에게 「대화 내용은 보내지 않았어」라고 합니다. 그런데 지금 서버는 보호자에게 앞뒤 2턴 발췌를 보냅니다. 어느 쪽으로 맞출지 정해야 합니다. 저는 화면 쪽(원문 없이 분류·긴급도·행동 안내만)으로 맞추는 안에 찬성입니다.
2. **로그인**: 11-15에 아이디·비밀번호 로그인을 서버에 넣을지, 체험 계정만 쓸지. 넣는다면 쿠키가 아니라 토큰을 헤더로 보내는 방식을 제안합니다(아이폰 Safari가 다른 주소의 쿠키를 막습니다).
3. **AI 답 표시**: `source`를 화면에 작은 배지로 보여 줄지.
4. **끊어 보내기**: 2-1의 방식(1.5초 묶기)으로 확정할지.
5. **프론트 코드를 저장소에 넣는 방법**: `frontend/` 폴더가 비어 있습니다. 재하 님이 직접 올려 주시면 그 위에서 맞추겠습니다.
6. **프론트 배포 주소**: 정해지면 서버에 등록합니다.
