# 휴대폰(안드로이드)에서 쓰기 — 11-15 방식과 이후 계획 v0.1

2026-11-11 · 대상: 팀 전원 · 기준: 저장소 `frontend/`·`backend/` 현재 코드

## 1. 11-15에는 「모바일 웹 + 홈 화면 설치」로 간다

아이는 집에서 자기 휴대폰(주로 안드로이드)으로 쓴다. 제출까지는 앱을 따로 만들지 않고, 지금 웹 앱을 휴대폰 브라우저로 열고 원하면 **홈 화면에 아이콘으로 추가**해 쓰게 한다.

이유
- 지금 구조가 그대로 돈다. 화면(React)과 API가 한 주소에서 나오고, 주소는 `#/...` 방식이라 새로고침해도 깨지지 않는다.
- 앱 포장(TWA·Capacitor)은 스토어 등록·심사·아동 대상 정책 준비가 필요하다. 나흘 안에 할 일이 아니다.
- 오프라인 저장 일꾼(service worker)은 「새로 배포했는데 옛 화면이 남는」 고장을 만들 수 있어 이번에는 넣지 않는다.

## 2. 심사위원이 폰으로 여는 법

1. **배포 주소**를 연다(Render 서비스 주소, 예: `https://chingu1-backend.onrender.com`). QR 코드는 성호가 만들어 README·발표 자료에 넣는다.
2. 로그인 화면 맨 아래 **「체험 계정으로 둘러보기」**를 누르면 아이디가 채워진다. 비밀번호는 모두 `demo1234`. 학생 `jiwoo`, 보호자 `jiwoo_mom`, 학습지도자 `kim_teacher`.
3. **첫 접속은 1분쯤 걸릴 수 있다.** 무료 서버는 15분 동안 아무도 안 쓰면 잠들고, 다음 요청 때 깨어난다. 요청이 5초를 넘으면 화면에 「서버를 깨우는 중이에요. 처음엔 1분쯤 걸릴 수 있어요.」가 뜬다. 잠들었다 깨면 서버 DB도 처음 상태로 돌아간다.
4. (선택) 크롬 메뉴 → 「홈 화면에 추가」. 아이콘을 누르면 주소창 없이 열린다.
5. 카카오톡으로 받은 링크는 카카오톡 안 브라우저로 열린다. 홈 화면 추가가 안 되고 로그인 기록도 따로라, 「다른 브라우저로 열기」를 권한다.
6. 데이터는 전부 합성(가짜)이다. 실제 아이 정보는 넣지 않는다.

## 3. 이번에 한 것

| 무엇 | 내용 |
|---|---|
| 홈 화면 설치 정보 | `frontend/public/manifest.webmanifest`: 이름 「AI 멘토」, 주소창 없이 열기(standalone), 세로 화면, 바탕·상단 색은 `tokens.css`의 크림색 |
| 아이콘 | 기존 캐릭터 그림(`mascot/horse/wave-face.png` 256px, `wave-avatar.png` 128px)을 그대로 쓴다. favicon·아이폰 아이콘도 같은 그림 |
| 화면 메타 | 키보드가 올라오면 화면 틀을 줄인다(`interactive-widget=resizes-content`, 수다 입력창이 가려지지 않게). 밝은 화면만 쓴다고 알린다(`color-scheme: light`, 다크 모드에서 색이 뒤집히지 않게) |
| 다시 열면 다시 읽기 | 앱을 내렸다 올리거나 인터넷이 돌아오면 학생 세션 단계와 수다 대화·남은 시간을 서버에서 다시 읽는다. 겹치면 요청은 한 번만. 아직 안 보낸(묶여 있는) 말은 지우지 않는다. 다시 읽기가 실패하면 지금 화면을 그대로 둔다 |
| 첫 접속 지연 안내 | 서버가 깨어 있는지 모를 때(앱을 처음 열었거나 마지막 응답 뒤 14분 넘게 지남) 요청이 5초를 넘으면 로딩 표시 옆에 한 줄. 방금 답한 서버가 AI 답을 만드느라 오래 걸리는 경우에는 띄우지 않는다 |

이미 고쳐져 있던 것(이전 점검에서 지적, 지금 코드에서 확인): 로그인 뒤 서버에 역할 헤더를 보냄, 학습·보호자·강사 기능만 서버로 보냄, `÷` 문제 그리기와 화면 오류 경계, 109·1388 전화 걸기(`tel:` 링크), 수다 끊어 보내기(`texts`·`/reply`).

## 4. 재하가 볼 것 (디자인 몫, 이번에 CSS는 안 건드림)

- **안전 영역 여백**: `viewport-fit=cover`라 노치·아래 제스처 바 밑까지 그린다. `.topbar`·`.bottom-actions`·`.tabbar`에 `env(safe-area-inset-top/bottom)` 여백이 필요하다(지금 `global.css`에 0건).
- **키보드**: 실제 폰에서 수다 입력 중 끝내기 버튼·빠른 말 칩·입력창이 다 보이는지. 화면이 좁으면 입력 중 칩 숨기기 검토.
- **누르는 곳 44px**: 40px인 작은 버튼·칩이 있다(디자인 규칙 2절 기준 44px).
- **다크 모드**: 폰을 다크 모드로 두고 삼성 인터넷·크롬에서 크림·민트가 그대로인지.
- **아이콘**: 지금 그림은 투명 배경 256px라 안드로이드에서 작게·흰 바탕 위에 보일 수 있다. 크롬의 「설치」 버튼 조건은 192·512px 아이콘이라 지금은 메뉴의 「홈 화면에 추가」로만 된다. 정사각 192·512 아이콘을 만들면 `manifest.webmanifest`의 `icons`에 이름만 바꿔 넣으면 된다. 캐릭터(띠)가 확정되면 그림도 바꾼다.
- **태블릿·폴드**: 넓은 화면에서는 작은 폰 테두리로 그려진다. 11-15는 그대로 둬도 된다.

## 5. 이후 로드맵

| 단계 | 무엇 | 언제 |
|---|---|---|
| 0 | 모바일 웹 + 홈 화면 설치 | **11-15(지금)** |
| 1 | PWA 오프라인 셸: service worker로 화면 파일만 저장(API는 저장하지 않음), 새 배포 때 「새 버전이 있어요」로 갱신 | 로그인·계정이 서버로 옮겨진 뒤 |
| 2 | TWA로 플레이스토어 등록: 크롬을 앱 껍데기로 쓴다. 사이트·앱 주인 증명 파일(Digital Asset Links), 개발자 계정, 아동 대상 정책(개인정보 처리방침·대상 연령 신고) 준비 | 학원 현장 검증 뒤, 스토어가 필요할 때 |
| 3 | 푸시 알림: 웹 푸시(service worker + 알림 허락) 또는 앱이면 FCM. 서버에는 구독 정보 저장, 「반드시 도착」해야 하는 보호자 알림은 보낼 것을 표에 적고 성공할 때까지 다시 보내는 큐(outbox)가 필요. 무료 서버는 잠들어서 정해진 시각 알림을 못 보낸다 | **지금 범위 밖** |

Capacitor(웹 화면을 앱 안에 넣는 방식)는 API를 절대 주소로 바꾸고 하드웨어 뒤로 가기를 직접 처리해야 해서, 네이티브 기능이 꼭 필요할 때만 검토한다.

지금 보호자 알림(🔴 포함)은 **앱을 열어야 보인다**. 발표에서 이 점을 숨기지 않는다.

## 6. 알려진 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| 데모 아이를 여럿이 같이 씀 | 서버에는 데모 아이가 한 명이고 세션은 하루 1개다. 심사위원 여럿이 학생으로 들어오면 같은 세션을 이어 쓰고, 첫 사람이 끝내면 다음 사람은 「오늘은 끝」을 본다 | 시연 전후 리셋(운영자만, 데모 토큰 필요). 사람마다 따로 쓰는 방법은 서버 결정 필요 |
| 학생-보호자 연결 코드 | 6자리 고정 코드, 만료·시도 제한이 없다. 코드만 알면 보호자로 연결된다. 지금은 브라우저 안 가짜 서버(mock)에만 있다 | 서버로 옮길 때 일회용·10분 만료·5회 실패 잠금·상대 승인 절차로 설계 |
| 계정이 기기마다 따로 | 로그인·가입·캐릭터 그림이 브라우저 저장소에만 있다. 브라우저 데이터 삭제·시크릿 창·카카오톡 안 브라우저에서는 사라진다 | 체험 계정으로 들어오게 안내 |
| 누구나 서버를 부를 수 있음 | 역할 헤더는 고정 값이라 공개 주소를 아는 사람은 누구나 AI 응답을 부를 수 있다 | AI 공급자 지출 한도 설정, 합성 데이터만 사용 |
| 실기기 미확인 | 지금까지 확인은 PC 화면 360×640 흉내뿐 | 갤럭시(삼성 인터넷·크롬)·아이폰 사파리로 키보드·뒤로 가기·화면 끄기·다크 모드 확인 |
