## ① 한 줄 결론

**파인튜닝(모델 자체를 추가 학습시키는 것)도 Ollama(내 서버에서 공개 모델을 직접 돌리는 도구)도 쓰지 않는다. 지금 구조(Haiku 5.5 API + 우리 프롬프트 + 서버 판정)가 맞다.** 여기에 「평가 문장으로 프롬프트 다듬기」와 「응답마다 live였는지 표시하기」만 더하면 짜고 친다는 의심에 답할 수 있다. 아이별 장기 기억은 지금 규칙(원문 저장 안 함, 72시간 만료)과 부딪치므로 11-15 이후 보호자 동의와 보관 기간을 정한 다음에 만든다.

## ③ 11-15까지 만들 것과 그 뒤로 미룰 것

**11-15까지 (모두 작은 변경)**
1. 메시지 응답에 `source`(live / scripted / fixed)를 넣는다. 지금은 어댑터 안에서 폴백(실패 시 대본으로 바꿔 답하는 것)이 일어나도 밖에서 알 수 없다. `/healthz`의 `llm_mode`는 *설정값*만 보여 주고, 그 턴에 실제로 무엇이 답했는지는 보여 주지 않는다.
2. 로그에 `source`, 응답 길이, `usage`(입력·출력 토큰 수), `request_id`를 남긴다. 원문은 남기지 않는다.
3. 스타일별 예시 대화 2~3개를 `prompts.py`에 상수로 넣고, `prompt_version`을 올려 기록한다.
4. 평가 문장 20개를 스타일 3종에 돌려 사람이 체크리스트로 채점한다(TK-37). 정답 누출, 3문장 초과, 반말/존댓말 위반, 이름 질문 여부를 본다.
5. 콘솔에서 월 지출 한도를 설정한다. 키는 Render 환경 변수 `LLM_API_KEY`에만 둔다.

**그 뒤로 미룰 것**
세션 요약 보관, 프롬프트 캐싱(지금 프롬프트는 너무 짧아 캐시가 적용되지 않는다), 모델 라우팅(강사 초안만 Sonnet), 키워드 + LLM 2단계 안전 분류, 로컬·국내 모델 검토, 임베딩 검색.

## ⑤ 질문 1~6에 대한 답

### 질문 1. 대화를 「학습」시키고 말투·성격을 세팅하려면

방법은 손이 덜 가는 것부터 네 단계다.

| 단계 | 무엇 | 우리 현황 | 비용·위험 |
|---|---|---|---|
| ① 시스템 프롬프트 | 역할, 말투, 금지 사항을 문장으로 준다 | 이미 있다(`prompts.py`, 부록 D) | 거의 없다 |
| ② 페르소나 카드 | 스타일별로 「이렇게 말한다 / 이렇게는 말하지 않는다」 5~8줄 | `STYLE_LINE`이 한 줄짜리 카드다. 늘리면 된다 | 토큰이 조금 는다 |
| ③ 예시 대화(few-shot) | 스타일마다 아이 말 → 멘토 답 2~3쌍을 프롬프트에 넣는다 | 없음 | 말투를 맞추는 데 가장 효과가 크다고 알려져 있다. 단, 예시 속 문제 숫자를 그대로 따라 할 수 있으니 시드와 다른 숫자를 쓴다 |
| ④ 평가 문장으로 개선(eval) | 고정 입력 20~30개를 돌려 채점 기준표로 점수를 매긴다. 프롬프트를 바꿀 때마다 다시 돌린다 | TK-37 예정 | 사람이 1회 30분 정도 채점 |
| ⑤ 파인튜닝 | 우리 대화 데이터로 모델 가중치를 추가 학습 | — | 아래 참고 |

**Claude 파인튜닝은 현재 쓸 수 있는 길이 확인되지 않는다.**
- Claude API: 공개 파인튜닝 기능 없음. 2차 자료 여러 곳이 같은 내용이며, 공식 문서에서 파인튜닝 항목은 찾지 못했다 [S1][S2].
- Amazon Bedrock: 유일하던 길은 **Claude 3 Haiku** 파인튜닝이었다(2024-11 정식 출시, 오리건 리전) [S3]. 그 모델은 Claude API에서 2026-04-20에 은퇴했다(claude-api 스킬 표). Bedrock에서도 수명이 끝났다는 2차 자료가 있다(2026-09-10) [S2]. AWS의 「파인튜닝 지원 모델」 공식 페이지는 이번에 내용을 읽지 못했다 → **확인 필요** [S4].
- 길이 열려 있다고 해도 우리 상황에는 맞지 않는다. 학습 데이터 수백~수천 쌍이 필요하고, 그 데이터는 결국 아이 대화인데 우리는 원문을 저장하지 않는다. 합성 데이터만으로는 프롬프트 + 예시 대화보다 낫다는 근거가 없다.

**추천.** ②+③+④로 간다. 「학습」이라고 발표하지 말고 「스타일 카드 + 예시 대화 + 평가 문장으로 반복 개선」이라고 말한다. 덧붙여, 같은 프롬프트가 매 요청 그대로 들어가므로 말투는 세션 내내 일관된다.

### 질문 2. Ollama(로컬 오픈 모델)로 될까

**시연용으로는 안 쓰는 게 낫고, 실제 서비스용으로도 2인 팀 범위를 넘는다.**

| 크기(4비트 양자화) | qwen3:4b 2.5GB, 8b 5.2GB, 14b 9.3GB, 32b 20GB. 양자화는 숫자 정밀도를 낮춰 용량을 줄이는 것이다. 실행하려면 이 크기에 대화 길이만큼 메모리가 더 필요하다 | [S6] |

### 질문 3. 「짜고 치는 것 아니냐」는 의심에 대해

**지금 구조에 대한 평가.** 대체로 옳다. 어댑터는 하나이고, live가 기본이며, scripted는 그 턴에 장애가 났을 때만 쓰인다(`FallbackAdapter`). 서버가 판정·힌트·시간을 정하는 것은 「대본」이 아니라 **설계 원칙**이다. 교육 앱에서 채점을 LLM에 맡기면 틀린 답을 맞다고 할 위험이 있어, 판정을 코드가 하는 편이 신뢰도가 더 높다. 이걸 발표에서 먼저 말한다.

**빈틈**
1. 폴백이 화면에 보이지 않는다. 대본으로 답해도 live처럼 보인다 → 의심을 키우는 지점이다.
2. `/healthz`의 `llm_mode`는 「키가 있고 LLM_MODE=live」라는 설정만 확인한다. 그 순간 API가 실제로 응답하는지는 확인하지 않는다.
3. 대본(`day3.yaml`)이 아직 5줄뿐이라 폴백이 나면 같은 문장이 반복된다.

**live임을 보이는 방법**(강한 순서)
- 심사위원이 **즉석에서 아무 말이나** 입력하게 한다. 대본에 없는 말에도 문맥에 맞는 답이 나오면 그것이 가장 강한 증거다.
- 응답 JSON에 `source: "live"`와 공급자 `request_id`를 넣고, 화면에는 작은 배지(「AI」/「대본」)를 표시한다.
- 같은 입력을 스타일만 바꿔(EBSP → DQSC) 두 번 보내 말투가 달라지는 것을 보여 준다.
- (선택) `/healthz?probe=1`로 짧은 실제 호출을 1회 하고 지연(ms)을 표시한다. 호출할 때마다 비용이 들지만 1원 미만이다.

**「커스텀 LLM」이 현실적으로 뜻하는 것.** 모델을 직접 학습시키는 것이 아니라, **API 모델 위에 우리가 소유한 층을 쌓는 것**이다.
(a) 스타일 카드와 예시 대화(우리 말투), (b) 서버 상태 요약(우리 교육 로직), (c) 안전 규칙과 키워드(우리 정책), (d) 아이별 구조화 기억(질문 5), (e) 평가 문장 세트(우리 품질 기준). 공급자를 바꿔도 이 다섯 가지는 남는다. 발표에서는 「모델은 빌리고, 교사는 우리가 만든다」로 표현할 수 있다.

**API에서 무엇을 가져와 조립하나.** 가져오는 것은 `messages.create` 호출 결과 하나다: 텍스트 블록, `stop_reason`, `usage`(토큰 수), 요청 id. 보내는 것은 ④ 그림의 `system`과 `messages`다. 비스트리밍이며 `effort: low`, `max_tokens: 1024`다. 덧붙여 claude-api 스킬 기준으로 Haiku 5.5는 `thinking: disabled`를 effort high 이하에서 **허용한다**. 코드 주석의 「thinking 끄기는 400」과 다르니, 끄면 지연과 비용이 줄어드는지 한 번 재 볼 만하다(확인 필요).

| 타임아웃·재시도 | 20초, SDK 재시도 1회, 실패하면 대본 | 적당하다. 리허설에서 지연 p95(느린 쪽 5% 경계값)를 재서 조정 |
| 거절 | `refusal`이면 대본으로 | Haiku 5.5에는 서버 측 자동 대체 모델이 없다(스킬). 지금 처리가 맞다 |
| 속도 제한 | — | Start 등급의 Haiku 5.5는 분당 4,000 요청, 입력 200만 토큰/분 [S13]. 우리 규모에선 문제없음. 새 조직은 이보다 낮은 「Evaluation」 등급에서 시작할 수 있다 → 시연 전에 콘솔에서 등급 확인 |
| 로그 | 단계·길이만(원문 없음) | `source`, `usage.input_tokens/output_tokens`, `request_id`, 지연 ms 추가 |
| 모니터링 | `/healthz` | 콘솔 Usage 페이지(토큰·비용·속도 제한 차트)를 쓴다 [S13]. 별도 도구는 필요 없음 |
| 프롬프트 버전 | 강사 초안만 `prompt_version` | 공부·수다 프롬프트에도 버전 상수를 두고 세션 행에 기록. 평가 결과표에 버전을 같이 적는다 |

**비용 추정(아이 1명, 하루 30분).** Haiku 5.5 가격: 입력 $0.10, 출력 $0.50(백만 토큰당, 프롬프트 10만 토큰 이하). 캐시 읽기 $0.01, 배치 50% 할인 [S14]. 새 토크나이저는 같은 글을 약 30% 더 많은 토큰으로 센다 [S14].

| | 가정 | 토큰 |
|---|---|---|
| 호출 수 | 같이 풀기 6 + 수다 6 + 다리 놓기 1 = 13회 | — |
| 입력 | 호출당 약 1,000(시스템 400~500 + 문제·힌트 + 최근 6턴) | 13,000 |
| 출력 | 답 약 200 + 생각 토큰 0~300(effort low, 실측 필요) | 2,600 ~ 6,500 |

### 질문 5. 아이마다 다른 정보

**세 층으로 나눠 저장한다.** 원칙: 문장이 아니라 **값**으로 저장한다.

```jsonc
// ① 프로필 — 학생 표 (지금 있음)
{ "student_id": "uuid", "grade_band": "초5-6", "style": "EBSP",
  "honorific": "hyung", "polite": false, "fence_codes": ["…4항목"] }

// ② 학습 상태 — 오개념 표 (있음) + 세션 표의 hint_level (있음)
{ "student_id": "uuid", "tag": "frac-div-invert", "first_wrong": "2026-11-09",
  "status": "open" }
{ "session_id": "uuid", "problem_id": "frac-div-03", "hint_level_max": 2,
  "result": "correct", "attempts": 3 }          // attempts는 지금 없음(추가 후보)

// ③ 대화 기억 — 세션 요약 (지금은 세션 표의 「학습 요약」 칸만)
{ "session_id": "uuid", "date": "2026-11-11", "prompt_version": "study-v1",
  "summary": ["분수÷자연수에서 역수 단계에서 막힘", "힌트 2에서 해결"],
  "chat_topics": ["학교", "시험"],                 // 주제 태그만, 내용 문장 없음
  "expires_at": null }                           // ← 보관 기간 결정 필요
```

**프롬프트에 넣는 방법.** 다음 세션 system에 「지난번: 역수 단계에서 막혔다, 힌트 2에서 해결」 한 줄만 넣는다. 별명은 넣지 않는다.

**지금 규칙과 부딪치는 지점**

| 하고 싶은 것 | 부딪치는 규칙 | 상태 |
|---|---|---|
| ①·② 저장과 프롬프트 사용 | 없음. 문장이 아니라 값이다 | **지금 가능** |
| 공부 요약(③ summary)을 72시간 넘게 보관 | 명세 4.2: 「백업 대상은 요약·오개념」이라 보관 자체는 허용. 다만 **요약 칸의 보관 기간이 명세에 적혀 있지 않다** | 결정 필요 |
| 수다 내용 요약을 저장 | 「원문 미저장」의 취지. 수다 요약은 사실상 아이 사생활 기록이고, 보호자 열람 범위 문제가 생긴다 | **충돌**. 주제 태그만 둘지 결정 필요 |
| 지난 대화 문장을 다시 프롬프트에 넣기 | 메시지는 72시간 뒤 만료된다 | **충돌**. 72시간 안에서만 가능 |
| 별명으로 부르기 | 「프롬프트에 별명 넣지 않음」 | 충돌. 하지 않는다 |

**장기 기억을 하려면 정할 것.** ① 무엇을(공부 요약만인가, 수다 주제 태그까지인가) ② 얼마나(예: 졸업·탈퇴까지, 또는 90일) ③ 보호자 동의 항목을 별도로 둘지(만 14세 미만이라 법정대리인 동의 대상. `docs/safety_secret_llm_legal_v0.1.md` 참고) ④ 아이·보호자가 기억을 보고 지울 수 있는 화면 ⑤ 공급자로 보내는 범위(요약도 국외 이전 대상이다).

### 질문 6. 기록이 방대해질 때 「손실 없이 압축」

솔직히 말하면, **이름은 같은 「압축」이지만 두 가지는 다른 것**이다.

| | 무손실 압축 | 의미 요약 |
|---|---|---|
| 무엇 | 원문을 zstd·gzip으로 줄여 보관하고, 풀면 한 글자도 안 틀리고 복원된다 | LLM이 「무슨 일이 있었나」를 몇 줄로 다시 쓴다 |
| 손실 | 없음 | **있다**. 빠지거나 틀리거나 지어낸 내용이 생길 수 있다 = 손실 압축 |
| 어디에 | 콜드 스토리지(싸고 느린 보관소) | 프롬프트용 기억 |
| 우리 규칙 | **불가능하다. 원문을 저장하지 않으므로 압축할 원문이 없다.** 치환본도 72시간 뒤 사라진다 | 가능하다. 단 위 표(질문 5)의 결정이 먼저 필요하다 |

**계층형 기억(나중에 할 때의 모양)**
```
최근 6턴 치환본 (72시간)  →  세션 요약 3줄 (값+짧은 문장)
   →  주간 요약 (오개념 변화·힌트 사용 추세)  →  사실 표 (오개념 태그, 스타일, 해결 여부)
```
아래로 갈수록 짧아지고 오래 간다. 프롬프트에는 사실 표 + 최근 세션 요약 1개 + 최근 6턴만 넣는다.

**요약 품질 검증.** ① 요약 안 사실이 원래 기록에 있는지 확인한다(만료 전에 자동 비교 1회). ② 요약에 이름·학교·전화가 다시 들어가지 않았는지 PII 필터를 한 번 더 돌린다. ③ 오개념 태그는 LLM이 아니라 서버 판정에서 나온 값만 쓴다.

**프롬프트 캐싱.** 매번 같은 앞부분(시스템 프롬프트)을 공급자가 잠시 기억해 두고 싸게 다시 읽는 기능이다. 캐시 읽기는 입력 가격의 0.1배다. 하지만 Haiku 5.5는 **512토큰 이상**이어야 캐시가 적용되고 [S15], 지금 시스템 프롬프트는 그보다 짧은 편이며 문제·힌트가 중간에 섞여 있어 앞부분이 고정되지 않는다. 스타일 카드와 예시 대화를 넣어 고정 부분이 512를 넘으면 그때 「고정 부분 → 문제·상태 → 대화」 순으로 바꾸고 캐시를 켠다. 기본 수명은 5분이다 [S15]. (참고로 `docs/llm_alternatives_v0.1.md`의 「Haiku 5.5 최소 캐시 286토큰」은 가격표의 **도구 사용 토큰 수**를 잘못 읽은 것이다. 정정이 필요하다.)

**임베딩 검색(RAG)이 필요한 시점.** RAG는 기록을 숫자 벡터로 바꿔 두고 비슷한 것만 찾아 넣는 방식이다. 이것이 필요해지는 때는 「지난달 그 얘기」처럼 **오래된 특정 기억을 골라 와야 할 때**다. 사실 표 + 최근 요약으로 충분한 동안은 필요 없다. 아이 1명의 기록이 수백 세션을 넘기 전에는 표 조회가 더 정확하고 싸다.

## ⑥ 위험과 법적 주의

1. **만 14세 미만 개인정보.** 장기 기억, 수다 요약, 공급자 전송은 모두 법정대리인 동의 범위 안에서만 할 수 있다. 동의 문구에 「AI 공급자(미국)로 치환본 전송」과 보관 기간을 넣는다(기존 문서 `llm_terms_minors`·`safety_secret_llm_legal` 참고).
2. **공급자 보관.** Anthropic 문서는 「대화 내용은 기본적으로 보관하지 않음(Covered Models 제외), 학습에 쓰지 않음」이라고 적고 있다. 다만 **안전 시스템에 걸린 대화는 최대 2년 보관될 수 있다** [S16]. 기존 문서의 「30일 보존」 표현과 차이가 있으니 상업 보존 정책 원문과 대조가 필요하다(**확인 필요**). Haiku 5.5는 Covered Model이 아니다.
3. **안전은 키워드 1회뿐이다.** 목록 밖 표현은 놓친다. 로컬 모델로 바꾸면 이 위험이 더 커진다.
4. **정답 누출.** 프롬프트에 정답은 없지만 풀이(hint_level 3)에서 모델이 정답을 말할 수 있다. 정답 문자열 사후 검사(있으면 좋음 ④)를 평가 문장에 포함한다.
5. **라이선스.** 오픈 모델을 쓸 경우 EXAONE은 NC(비상업)이고, Gemma 3 이하는 자체 약관이다. 「오픈」이 곧 「상업 가능」은 아니다.
6. **「학습시켰다」는 표현.** 파인튜닝을 하지 않았는데 「학습」이라고 말하면 과장이 된다. 「프롬프트 설계 + 평가 기반 개선」이라고 말한다.
