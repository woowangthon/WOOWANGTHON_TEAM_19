## 1. 한 장 요약

하루 한 번, 학원 수업 뒤 30분. 아이는 친구1과 **오늘 틀린 것 하나를 다시 풀고**(20분), **오늘 있었던 일을 가볍게 말하고**(10분), **어른에게 무엇이 가는지 자기 눈으로 보고** 끝낸다. 강사는 수업 뒤 **1~2분 메모**만 남기면 학부모용 코멘트 초안이 바로 나온다. 보호자는 **하루 한 줄**(오늘 배운 것 + 아이가 낸 퀴즈 1개) 카드를 본다. 위험 신호(🔴, 자해·자살)만 즉시 간다. 11-15 범위는 5절.

듀오링고에서 가져오는 것은 그림이나 마스코트가 아니라 **규칙 네 가지**다: ① 성공 조건은 하나(하루 1회 전환 진입 = 연속 +1) ② 첫 7일을 따로 설계 ③ 쉬는 날은 기록이 끊기지 않게(프리즈) ④ 알림은 하루 1회, 목표를 상기하는 문장으로. 리그·하트·죄책감 알림은 가져오지 않는다(2절). 11-15에는 ①만 동작.

### 학원 앱 (클래스업·아이엠클래스·맥가이·어나더클래스·아카데미UP·출결톡)

- **출결·알림장·결제는 만들지 않는다.** 알림톡 건당 9~18원 가격 경쟁 영역이고 어디나 있다. 우리는 "수업 뒤 피드백·상담 기록의 **생성** 단계"에 선다.
- **학생이 직접 쓰는 화면이 시장 공백이다.** 기존 학원 앱의 학생 앱은 출결 체크용뿐. 친구1이 아이에게 직접 말을 거는 면이 신규 가치.
- **강사 메모 → AI 초안 → 강사 승인 → 공개 토글** 순서는 현장 관행(클래스업의 "상담 기본 비공개 + 공개 토글", "AI는 뼈대, 사람이 사실 확인")을 그대로 UX로 옮긴 것.
- **강사의 병목은 글쓰기**다. 수업 뒤 메모 1~2분, 집계 3~5분, **학부모용 글쓰기 20~30분**. 소규모 학원 사례로 지도 보고서 40건/월 ≈ 10시간.
- **알림 피로**: 아이엠스쿨 리뷰 "쓸데없는 알림이 너무 많이 와요". 보호자별로 알림 종류를 고르게 한다.

끝난 날 두 번째 접속은 "내일 봐". "하루"는 **Asia/Seoul 날짜**(서버가 UTC여도).

**문제와 정답 판정 (「내 제안」)**
- **시드 문제 20개**(초등 5~6 분수·소수, 9절). 정답 키·태그·힌트 2단계·풀이·금지 문자열(부록 B). 구조는 과목 무관.
- 맞았는지는 **정답 키로** 판정. LLM은 코칭만.
- 태그는 고정 목록(미정). 퀴즈 3개를 뽑으려면 **태그당 4문제 이상** → 태그 최대 5개.
- 오개념 「열림」은 hint_level 3 도달 때만. 해소·재발은 이번엔 하지 않음(시드에 해소 카드 1장).
- 강사 지정도 시드 목록 드롭다운.

**허용 입력 형식** (전부 분수 값으로 바꿔 비교. 테스트 20문제 × 3표기 = 60건)

| 아이 입력 | 해석 | 예 → 값 |
| --- | --- | --- |
| `a/b` | 분수 | 3/8 → 3/8 |
| 소수 | 유한소수만(순환소수 근사는 오답) | 0.375 → 3/8 |
| `b분의 a` | 한글 분수 | 8분의 3 → 3/8 |
| `n a/b` | 대분수(정수 + 공백 + 분수) | 1 1/2 → 3/2 |
| `a÷b` | 나눗셈식 | 3÷8 → 3/8 |
| 패턴 없음 | **판정 안 함** → 코칭만 | "이거 어떻게 해?" |

형식을 요구하는 문제("기약분수로")는 `kind = "exact"`(부록 B).

**끊어 보내기 — 턴 묶기 + 서버 흡수 (11-11 성호 결정, 결정 DB 등록 대기)**
- 아이는 "음…" "3/8?" "맞아?"처럼 끊어 보내거나 뭉쳐 보낸다. **입력창·전송 버튼은 열어 둔다.** 프론트가 약 1.5초 안에 보낸 조각을 한 턴(`texts`, 최대 5개)으로 묶어 보낸다.
- **판정은 조각마다** 위 표 그대로(조각 전체가 답 형식일 때만, 문장 속 답은 판정하지 않음). study 단계 조각의 판정은 `messages.judge`에 저장되고, 정답 여부·시도 수는 이 저장값만 읽는다(재판정 없음).
- 🔴 키워드는 **조각마다 즉시** 검사한다. 멘토 답을 기다리는 중이어도 바로 crisis.
- 멘토 답을 만드는 중(`sessions.replying_until`이 유효)에 온 조각은 서버가 저장·🔴 검사·판정만 하고 LLM을 부르지 않는다(**흡수**, 응답 `queued: true`). 답이 끝나면 응답의 `pending: true`를 보고 프론트가 `POST /sessions/{id}/reply`로 남은 조각에 한 번 더 답을 받는다.
- 한 번의 멘토 답은 「아직 답 안 된 조각 전부」를 한 user 턴으로 받는다. LLM에 가는 판정은 그 조각들의 요약(correct가 하나라도 있으면 correct, 아니면 wrong이 있으면 wrong, 아니면 없음)이다.

### 3.3 보호자

- **하루 한 줄** (다리 놓기가 끝나면 **카드 저장**, 푸시는 후속): "오늘 분수 나눗셈을 다시 풀었어요. 민수가 낸 퀴즈: 3/4 ÷ 2는?" 대화 내용은 없다.
- **주 1회 요약**: 이번엔 하지 않음.
- **🔴 즉시**: 자해·자살만. 아이에게 먼저 알리고 보낼 발췌(앞뒤 2턴, 300자)를 아이 화면에 보여 준 뒤 보호자 카드 맨 위에 1줄 + 109·1388. 그 부분만 간다. 수신자는 **보호자 계정 1곳**, 연락처는 저장만. 학대 분기는 이번엔 하지 않음.
- 열람 범위 = 요약만(9절). 알림 종류 선택은 이번엔 하지 않음.
- 「오늘」 카드는 하나: (있으면) 🔴 1줄 + 아이 한 줄 + 퀴즈 + 강사 코멘트 칸(승인 전엔 "선생님이 확인하면 여기에 와요").

### 3.4 강사

| 단계 | 내용 | 시간 |
| --- | --- | --- |
| 수업 뒤 메모 | 구조화 3칸(다룬 것 / 막힌 것 / 숙제) + 자유 메모 한 줄 | 1~2분/명 |
| 오늘 할 것 지정 | 시드 드롭다운에서 **단원/성취기준으로 골라** 1개 → 다음 세션 | 10초 |
| AI 초안 | **메모 저장 즉시**, 입력 = 메모 + (있으면) 학습 요약 3줄, **재생성 없음**. 수다 내용은 강사에게도 안 감 | 자동, 실패 시 템플릿 |
| 승인 | 고쳐서 승인 / 보내지 않음. **사실 칸은 AI가 아니라 구조화 필드에서** | 30초 |
| 공개 | 기본 비공개, 승인 시 보호자 카드 | — |

**초안 규칙:** 메모 저장 순간 한 번. 요약이 있으면 넣고 없으면 메모만. 재생성·만료·밤 10시 배치는 이번엔 하지 않음. **시연 순서: 아이 세션 → 강사 메모 → 승인 → 보호자 화면**(그래야 요약이 들어간다). 반 대시보드는 후속.

**고쳐 저장:** 승인 전(`draft`) 초안 문장은 강사가 고쳐 저장할 수 있다 — 재생성이 아니라 사람이 고친 문장을 PII 치환해 `draft_body`에 덮어쓴다. 승인·보내지 않음 뒤에는 409 `note_closed`(11-11).

## 4. 기술 흐름 (입력 → 처리 → 저장 → 출력) — v0.3

원칙. ① **전환·힌트·판정·시간 마감은 서버 코드**, LLM은 문장만. ② **LLM은 어댑터 하나** 뒤(live / scripted). ③ **세션 상태는 DB 행**에. ④ **비스트리밍**: 답은 한 번에, 기다리는 동안 "생각 중…". 입력은 열어 두고 1.5초 묶기 + 서버 흡수(3.2, 11-11 성호 결정, 결정 DB 등록 대기).

- **today_task:** 강사 PUT → 학생 행 두 칸(다시 지정하면 덮어씀). 세션 시작 시 세션.problem_id로 복사하고 비운다. 오늘 이미 끝났으면 다음 세션에 읽힌다.
- **시간 칸:** 단계 진입 시 phase_started_at = now, deadline_at = now + (chat 10분 / 그 외 null) ÷ timer_scale. **서버가 매 요청마다 now > deadline_at이면 먼저 전이한다.** 클라이언트 타이머는 표시용.
- **삭제는 만료 시각 방식.** 🔴 판정 시 같은 트랜잭션에서 flag·알림 행·발췌를 쓰고 메시지는 그대로 만료되게 둔다. 삭제 잡은 `DELETE WHERE 만료 < now()` 한 줄.
- **PII 필터(범위 축소).** ① 프롬프트 조립 단일 함수: 입력은 {학년대, 호칭, 성격 코드, 말투, 울타리 코드, 문제, hint_level, 치환된 최근 턴}뿐. **별명을 넣지 않고 "너"로 부른다.** ② 입력 필터(아이 텍스트·강사 메모): **전화·이메일 정규식 + DB에 있는 별명·연락처 치환 + "~학원 / ~초등학교 / ~중학교" 접미사 단어 치환** → `[전화]` `[이메일]` `[이름]` `[학교]`. **임의 이름("우리 반 지민이")은 잡지 않는다.** ③ 검증: 테스트 문장 20개(미정)를 pytest로. CI 테스트(코드 올릴 때마다 자동으로 도는 검사)는 지금 없다.
- **원문은 저장하지 않는다.** 메시지는 치환본만. 백업 대상은 요약·오개념뿐. 시드·녹화는 합성임을 README에 적는다.
- **공급자 쪽 보관은 우리가 못 지운다.** ZDR(입력 무보관: 공급자가 보낸 문장을 안 남기는 계약 옵션, 기본 API 키엔 없음)은 주장하지 않는다. 공급자 약관 확인 후 **"학습에 쓰지 않으며 N일 보관"으로 사실만 적는다(확인 담당: 9절).** 공급자는 재수탁자(우리가 다시 맡기는 쪽)라 위탁 문서에 포함.

### 4.3 안전 규칙 (친구1 문서 3단계를 처리 규칙으로)

| 단계 | 감지 | 친구1의 행동 | 시스템 |
| --- | --- | --- | --- |
| 🟢 일상 | 다툼·시험 걱정 | 들어 준다 | 전달 없음 |
| 🟡 주의 | 반복 고민 | 먼저 묻지 않는다(프롬프트 문장) | 감지·누적은 **이번엔 하지 않음** |
| 🔴 자해·자살 | **키워드 1회** | 고정 문장 "지금 어른에게 알릴게"(LLM 없음), 발췌 표시, 109·1388 | crisis, 다리 놓기 건너뜀, 연속 깎지 않음. 알림 행 → 보호자 카드 |

학대 의심 분기는 이번엔 하지 않음.

- **키워드·정규식 1회.** 모든 단계, 입력마다, LLM 호출 전. 걸리면 LLM 없이 즉시 crisis. 목록은 부록 A.
- **한계(정정):** 키워드만 쓰므로 **덜 잡는 쪽**이다. 목록 밖 표현은 놓칠 수 있고 11-15에는 잡는 장치가 없다. 평가 문장 20개로 미탐·오탐 수를 세어 4.10에 적는다.
- **후속: 2단계 설계**(키워드 + LLM 분류 앞·뒤). 슬라이드 한 줄.
- **사후 검사(있으면 좋음 ④):** 응답 전문을 문장 단위로 정답 문자열·forbidden[] 검사 → 걸리면 고정 문장.
- 🔴 오탐 확인 버튼은 후속. **시연 🔴 = 부록 A의 R1.**

### 4.5 상태기계

**상태 enum (DB·API는 같은 문자열)**

| DB 값 | 한글 이름 | API 문자열 | 화면 이름 |
| --- | --- | --- | --- |
| (행 없음) | 시작 전 | session = null | 아이 「오늘」 |
| study | 같이 풀기 | "study" | 「같이 풀기」 |
| chat | 수다 | "chat" | 「수다」 |
| bridge | 다리 놓기 | "bridge" | 「다리 놓기」 |
| ended | 끝 | "ended" | 「끝」 → 다음 접속은 "내일 봐" |
| crisis | 🔴 종료 | "crisis" | 아이 🔴 화면 |

study 안의 hint_level: **0 = 풀이 중, 1 = 힌트1, 2 = 힌트2, 3 = 풀이 보기.**

| # | 전 | 조건 | 후 |
| --- | --- | --- | --- |
| 1 | 시작 전 | 오늘 할 것 있음 + 시작 | study, hint_level 0 |
| 2 | study (hint 0~2) | 힌트 버튼 | hint_level +1. 3이면 오개념 open |
| 3 | study | 정답 뒤 "수다할래?" 예 / 끝낼래 | chat / bridge (**연속 +1**) |
| 4 | study (hint_level 3, 풀이 보기) | "봤어" 뒤 예 / 끝낼래 | chat / bridge (**연속 +1**) |
| 5 | chat | 수다 끝내기 버튼 또는 now > deadline_at | bridge |
| 6 | bridge | 아이가 확인(퀴즈 없어도) | ended |
| 7 | study / chat / bridge | 키워드 🔴 | crisis (다리 놓기 건너뜀) |

오답은 상태를 바꾸지 않는다(판정 + 코칭). 멘토 답 생성 중 표시(`replying_until`)는 상태가 아니라 세션 행의 칸이다: 4번 요청이 LLM 호출 전 짧은 트랜잭션에서 세우고 답 저장 트랜잭션에서 푼다. 그 사이 🔴이 오면 crisis가 이기고 늦게 온 답은 버린다(11-11). 새로고침하면 /me/today가 진행 중 세션을 돌려준다. **연속 +1은 전환(chat 또는 bridge) 진입 시 한 번**(streak_applied로 중복 방지, crisis여도 깎지 않음).

중단·수다만·재발은 이번엔 하지 않음.

**강사코멘트:** 메모 저장 → draft(즉시 생성, 실패 시 템플릿) → published / skipped. **오개념:** hint_level 3 도달 → open. resolved는 시드에만.

### 4.8 시연 안정성 장치

1. 어댑터 2모드 **live / scripted**(부록 C). 환경변수 `LLM_MODE`. live 실패 시 그 턴만 scripted 폴백.
2. 타임아웃 20초(리허설 실측 후 조정).
3. 시드 **day3 하나**: 연속 3일, 미해결 오개념 2개 + 해소 카드 1장, 오늘 할 것 지정됨, 오늘 강사 메모 없음. style = EBSP / EQLC / DQSC + honorific + polite(11-08 제안, 재하 확인 대기). 리셋 2초. fresh(온보딩)는 이번엔 하지 않음.
4. GET은 빈 값도 정상 형태로, 화면마다 빈 상태 문구.
5. **배포 URL 필수**: 단일 프로세스를 호스팅(Postgres)에 올리고, 심사위원용은 live + scripted 폴백 + day3 + 역할 선택. 현장·영상은 로컬 scripted.
6. /healthz 확인.
7. **오프라인 리허설이 통과 조건:** Wi-Fi 끄고 scripted로 대본 완주.
8. **대본 5분 = 세션 A(정상) → 리셋 → 세션 B(🔴).** A(EBSP·형·반말): 오늘 → 풀기(오답 → 힌트 → 정답) → 수다 1턴 → 다리 놓기 → 끝 → 강사 메모 → 승인 → 보호자 카드. 리셋(EQLC·언니·존댓말, 「내 제안」). B: 풀기 1턴 → 수다 중 R1 → 🔴 화면 → 보호자 🔴 1줄. 분 배분은 대본 담당(미정).

### 4.9 제출물용 "프라이버시 설계 한 장" (초안)

1. 아이에게서 모으는 것은 별명·학년대·오늘 푼 문제·세 줄 요약뿐이다. 실명·사진·위치·연락처는 받지 않는다. 보호자 연락처 1칸만 암호화해 둔다.
2. 보호자 동의는 학원 명의로, 휴대폰 본인인증(개인정보보호법 시행령 17조의2 1항 3호)으로 확인한다. 항목별로 따로 받는다. 시연판에는 이 화면이 없다.
3. **AI에는 별명·연락처가 가지 않는다.** 프롬프트에 별명을 넣지 않고, 아이가 쓴 전화번호·이메일, 등록된 별명·연락처, "~학원·~초등학교·~중학교" 이름은 보내기 전에 지운다. 그 밖의 이름(친구 이름 등)은 자동으로 잡지 못한다.
4. **AI 공급자는 (미정).** 약관 확인 후 "입력을 학습에 쓰지 않으며 공급자가 N일 보관한다"를 사실대로 적는다(확인 담당: 9절). 국외 이전은 따로 알리고 동의받는다.
5. 대화(지운 본)는 72시간 뒤 만료된다. 원문은 저장하지 않는다. 남는 것은 요약과 오개념 태그다.
6. 보호자는 하루 한 줄 카드만 본다. 원문 열람 화면은 만들지 않았다.
7. **자해·자살 신호에만 예외가 있다.** 그때도 앞뒤 2턴(300자 이내)만, 아이 화면에 먼저 보여 주고 보호자에게 간다.
8. 서버 로그에는 대화 본문을 남기지 않는다.
9. 탈퇴하면 학생 행과 연결된 기록을 모두 지운다.
10. 시연 데이터는 전부 합성이다. 실제 학생 데이터는 한 건도 없다.

## 7. 설문과 검증

### 7.1 원칙 (Pew·통계개발원·NN/g 기준)

한 문항 한 개념. 앱 소개는 설문 **뒤**에. 동의/비동의형 대신 양자택일 또는 빈도. 가정형("있었다면")은 1문항만, 앞에 실제 과거 행동을 묻고 뒤에 확신도를 붙임. 척도는 5점, 라벨 전부 표기. 자유서술은 마지막 1문항, 사건 하나를 요청. 배포 전 비팀원 2명에게 소리 내어 읽게 한다.

### 7.2 문항 초안

**(가) 가르치는 사람** — 교사·예비교사·학원 강사 경험자

1. 가르친 경험(복수): 학교 교사 / 학원 강사 / 과외·멘토링 / 교육실습 / 없음. 주로 맡은 학년: 초등 저·고 / 중 / 고.
2. 지난 1년간 학생이 공부 외 고민(친구·가족·기분)을 당신에게 털어놓은 빈도: 전혀 없음 / 거의 없음 / 가끔 / 자주 / 매우 자주.
3. 학생이 AI(챗GPT·제타 등)에게 고민을 말한다는 것을 알거나 들은 적: 있다 / 없다 / 모르겠다. 있다면 가장 걱정된 것 1개: 유해·부정확 답변 / 의존 / 비밀 유출 / 현실 관계 단절 / 특별히 없음 / 기타.
4. 양자택일. A "학생의 AI 대화 **요약**을 받으면 지도에 도움이 된다" vs B "요약이 전달되는 걸 알면 학생이 솔직히 말하지 않아 역효과다": A에 가깝다 / 약간 A / 약간 B / B에 가깝다.
5. (서술) 이런 서비스가 학원에 들어온다면 반드시 있어야 할 안전장치, 또는 절대 하면 안 되는 것 하나.

**(나) 또래 대학생** — 회고형

1. 초등 4~6학년 때 고민을 주로 말한 상대(1개): 부모 / 형제·자매 / 친구 / 학교·학원 선생님 / 아무에게도 안 함 / 기타.
2. 그 시기에 "누구에게도 말 못한 고민"이 있었던 정도: 전혀 / 거의 없음 / 가끔 / 자주 / 매우 자주.
3. 최근 3개월, AI 챗봇에 고민이나 감정을 이야기한 경험: 없음 / 1~2회 / 월 1회 이상 / 주 1회 이상.
4. "초등학생 때 지금 같은 AI 형·언니가 있었다면 고민을 털어놓았을 것이다": 전혀 아니다 / 아니다 / 보통 / 그렇다 / 매우 그렇다. 이 답에 대한 확신: 확신함 / 반반 / 잘 모르겠음.
5. (서술) 그 대화의 요약이 부모님이나 학원 선생님에게 간다고 알았다면, 안 했을 말이 있었을까요? 한 문장으로.

11-05 회의에서 성호가 말한 "그때 그게 있었다면 어떻게 했을까"는 (나)-4, 재하가 말한 "학생이었으면 이걸로 관리하면 어떻겠냐"는 (가)-4에 들어 있다.

## 8. 디자인 방향

브리프: 아이(10~15세)·보호자·강사가 쓰는 앱. 학원 연습장 위에서 일어나는 일. 듀오링고 초록 마스코트, SaaS 카드 묶음, 크림 바탕에 테라코타 포인트는 피한다. 팀에 디자이너가 없으므로 **그림이 아니라 서체와 한 가지 색으로** 성격을 낸다.

원칙

1. **종이 위 형광펜.** 포인트 색은 화면당 한 곳. 그래서 아이 눈이 다음 할 일로 간다.
2. **동물 마스코트 셋 = 스타일 셋.** (11-06 수정. "그림 없이 말투로만"은 팀이 기각: 대화 상대의 공통 이미지가 없으면 각자 다른 앱을 떠올린다.) 사람이 아닌 동물, 나이 없는 존재. 시안은 시안/캐릭터_시안.html. **11-08 제안, 재하 확인 대기:** 하나 대신 셋, 형/언니가 아니라 성격(스타일)에 연결 — 같이 풀어주는(EBSP) / 들어주는(EQLC) / 짚어주는(DQSC). 아이는 처음 한 번 마스코트(=스타일)·호칭·반말/존댓말을 한 화면에서 고르고, 스타일은 말투·힌트 방식·칭찬 방식으로 드러난다. 11-15는 정지 이미지 3개, 표정 변화는 시연용 캐릭터 한 마리만. (11-09: 그림체 십이지신 방향, 동물 미정.)
3. **어른 화면은 밀도가 다르다.** 아이: 큰 글자, 한 번에 하나, 버튼 하나. 보호자·강사: 문장과 표, 작은 글자, 편집 가능.
4. **숫자를 전시하지 않는다.** XP·점수·순위 없음. 연속은 "3일째 같이 했어" 문장. 오개념은 숫자가 아니라 카드.
5. **알림 문구는 기다리는 말.** "민수야, 오늘 분수 하나만 같이 풀자" 식. 놓쳤을 때 "연속이 끊겼어요" 같은 손실 강조 금지.
6. **움직임은 두 번.** 세션 끝 "오늘 끝" 카드가 접히는 순간, 오개념이 해소되어 카드가 넘어가는 순간. 그 외 전환 효과 없음.

레이아웃: 모바일 1열, 왼쪽 정렬, 폭 최대 480px. 아이 화면의 첫 화면은 숫자판이 아니라 **친구1의 한마디**가 가장 크다.

```
┌──────────────────────────┐
│ 3일째 같이 했어            │  ← 연필 회색, 작게
│                          │
│ 민수야, 어제 막힌          │  ← 마루 부리, 가장 큼
│ 분수 나눗셈 하나만         │
│ 같이 풀자.                │
│                          │
│ ┌──────────────────────┐ │
│ │ ▮ 시작하기 (20분)      │ │  ← 형광펜 노랑, 화면에서 유일한 색
│ └──────────────────────┘ │
│                          │
│ 오늘 수업: 분수 ÷ 자연수    │  ← 강사가 지정한 것
│ 내 오개념 카드 2장          │
└──────────────────────────┘
```

생성형 기본값과 겹치는지 점검: 크림+테라코타 아님, 어두운 바탕+형광 아님, 카드 묶음 아님, 대문자 라벨·가운뎃점 메타 없음. 형광펜 노랑과 명조 말풍선은 이 브리프(학원·연습장·형의 목소리)에서 나온 선택이다.

## 부록 B. 시드 문제 JSON 스키마 (예시 1개)

```json
{
  "id": "frac-div-03",
  "tag": "frac-div-nat",
  "standard": { "code": "[6수01-xx]", "curriculum": "2022", "unit": "분수의 나눗셈" },
  "text": "3/4 ÷ 2 를 계산해 보세요.",
  "expr": "3/4 / 2",
  "answer": { "kind": "value", "value": "3/8", "accepted": ["3/8", "0.375", "8분의 3", "3÷8"] },
  "hint1": "÷ 2 는 × 1/2 과 같아요.",
  "hint2": "3/4 × 1/2 에서 분자는 분자끼리, 분모는 분모끼리 곱해 봐요.",
  "solution": "3/4 ÷ 2 = 3/4 × 1/2 = 3/8",
  "forbidden": ["3/8", "0.375", "8분의 3"]
}
```

- `kind`: `"value"` = 값이 같으면 정답(accepted[]는 테스트용) / `"exact"` = accepted[] 표기만.
- `forbidden`: 힌트·응답에 나오면 안 되는 문자열(사후 검사용). 태그 목록은 미정, 태그당 4개 이상.
- `standard`: 성취기준 코드·교육과정 버전·단원. 강사는 단원/성취기준으로 범위를 지정한다. 2015/2022 개정이 같은 코드에 다른 내용을 쓰는 경우가 있어 `curriculum`을 같이 저장(재하 TK-29). 코드 번호 `xx`는 **시드 작성 시 확인**.
- `expr`: 검증용 기계식. 시드 작성 시 이 식을 계산해 `answer.value`와 같은지 확인한다.

## 부록 D. 프롬프트 3종 초안 + 성격 코드 최소 정의

**학습 (prompts/study.txt)**
```
너는 초등 5~6학년 아이와 수학 문제 하나를 같이 푸는 {호칭}이다. 말투: {말투 조각}
아이를 "너"라고 부르고 이름을 묻지 않는다.
문제: {text} / 현재 힌트 단계: {hint_level} / 이 단계에서 써도 되는 힌트: {hint_n}
판정은 서버가 이미 했다: {judge}. 판정을 바꾸거나 다시 하지 않는다.
정답과 풀이 전체를 말하지 않는다. 다음 한 걸음만 묻는다.
2~3문장, 쉬운 말. 수학 밖 얘기는 "공부 끝나고 얘기하자"로 돌린다.
```

**수다 (prompts/chat.txt)**
```
너는 공부를 마친 아이와 10분 동안 가볍게 이야기하는 {호칭}이다. 말투: {말투 조각}
먼저 캐묻지 않는다. 아이가 꺼낸 이야기에만 짧게 반응하고 질문은 하나까지.
조언·진단을 하지 않고, "비밀 지켜 줄게"라고 약속하지 않는다.
같은 고민을 다시 꺼내면 "같이 어른께 말해 볼까"를 제안할 수 있다.

```

**초안 (prompts/draft.txt)** — 구조화 출력(LLM이 정해진 JSON 모양으로 답하게 하는 것)

```
숙제·점수는 쓰지 않는다(서버가 사실 칸에 따로 붙인다).
학습 요약이 없으면 메모만으로 쓴다.
```

**스타일 코드 → 말투 조각 (최소 정의, 「내 제안」)** — {말투 조각}은 아이가 고른 **스타일의 4글자 코드**에서 나오고, 끝에 반말/존댓말 지시 한 줄이 붙는다. {호칭}·반말/존댓말은 코드와 독립(아이가 따로 고름). 8문항(2문항씩 4축) 검사는 있으면 좋음 1순위로, 결과 코드(16개)가 가장 가까운 스타일을 추천한다. 전체 매핑표·문항은 발표 슬라이드.

| 축 | 글자 | 뜻 |
| --- | --- | --- |
| 힌트 방식 | D / E | 막힌 곳을 바로 짚어 줌 / 스스로 찾게 질문 |
| 칭찬 방식 | B / Q | 크게 / 조용히 |
| 말 길이 | S / L | 짧게 / 자세히 |

**학습 요약 3줄 (세션.학습 요약)**
1. 푼 것 — 코드: "{태그 이름} 문제 1개, 힌트 {hint_level}단계에서 {정답 / 풀이 보기}"
2. 막힌 곳 — LLM 한 구절(실패 시 "막힌 곳 기록 없음")
3. 다음 — 코드: "미해결: {open 태그 목록}" 또는 "미해결 없음"

보호자 한 줄 = "오늘 {태그 이름}을 다시 풀었어요." + 퀴즈(시드 text). 폴백도 같은 모양.
