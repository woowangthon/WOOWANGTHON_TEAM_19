# 문제 생성 지시 (공통, v2)

너는 「친구1」(학원 초·중학생용 AI 멘토 앱) 문제 은행의 문제를 만든다. 아이는 집에서 폰 채팅으로 문제를 풀고, AI 멘토가 힌트1 → 힌트2 → 풀이를 차례로 준다. 정답은 서버 코드만 판정하고, 멘토의 말에 정답이 섞이면 서버가 그 말을 버린다. 그래서 **힌트가 답을 흘리지 않으면서도 실제로 도움이 되는 것**이 이 일에서 가장 어렵고 가장 중요하다. 시범 60문제에서 정답이 틀린 문제는 없었지만 38문제를 고쳐야 했고, 그 대부분이 힌트2가 판정을 다 해 줘서 아이가 할 일이 남지 않은 경우였다.

## 입력

- 단원 설계도: `bank/v2_blueprint_<subject>.json`에서 지정된 `unit_id` 한 개. `problem_types`의 유형·개수·난이도, `core_concepts`, `misconceptions`, `out_of_scope`, `answer_rules`, `notes`를 따른다.
- 설계도 수정 목록: `bank/pilot_blueprint_fixes.md`. 「모든 단원 공통」 절과 네 단원 절이 있으면 설계도보다 먼저 따른다.
- 공통 규칙: `bank/v2_generation_rules_v2.md` 전부. 설계도와 다르면 규칙이 이긴다.
- 보기 삼을 문제: `bank/pilot_review.md`의 수정 목록(나쁜 힌트와 고친 힌트가 나란히 있다).

경로 기준: `seed/drafts/`(저장소 안)

## 출력

`bank/problems/<unit_id>.json` — JSON 배열, 설계도 count 합만큼(보통 20). 각 문제:

```json
{
  "id": "<unit_id>-01",
  "unit_id": "<unit_id>",
  "tag": "<unit_id>",
  "subject": "math|korean|english",
  "grade": 4,
  "standard": {"code": "[4수01-01]", "curriculum": "2022", "unit": "<설계도 unit_name>"},
  "difficulty": "easy|medium|hard",
  "problem_type": "<설계도 problem_types[].type 글자 그대로>",
  "targets_misconception": "<설계도 misconceptions의 한 문장 글자 그대로, 없으면 빈 문자열>",
  "text": "<문제. 객관식은 보기 ①~④를 한 줄에 하나씩. 마지막 줄은 규칙 3.1 표의 입력 안내 문구>",
  "expr": "<수학만: 정답을 계산하는 파이썬 산술식. 정수와 + - * / 괄호만>",
  "verify": "expr|manual",
  "verify_note": "<verify가 manual이거나 영어·국어 단답이면 필수: 무엇을 대입·대조해 확인했는지>",
  "answer": {"kind": "value|choice|text", "value": "<정답>", "accepted": ["<아이 입력으로 받을 표기>"]},
  "hint1": "<어디를 볼지. 질문 꼴. 판정을 내리지 않는다>",
  "hint2": "<판단 기준 + 중간 판정 하나까지. 마지막 판정은 남긴다>",
  "after_hint2": "<힌트2 뒤에 아이가 스스로 해야 하는 판단·계산 한 줄>",
  "solution": "<풀이. 정답 포함. 객관식은 오답 보기마다 틀린 까닭>",
  "forbidden": ["<멘토 말에 나오면 안 되는 표기 — 규칙 7절>"],
  "source": "ai",
  "generator": "<모델 id>",
  "review": "none|needs_review",
  "review_note": "<needs_review면 필수. [사전]/[유일성]/[범위]/[코드]/[난이도]/[오개념] 코드로 시작>"
}
```

국어·영어는 `expr`을 쓰지 않는다. 객관식의 `verify`는 `"manual"`이고 `verify_note`는 생략할 수 있다(풀이에 오답 까닭이 있으므로).

## 만드는 순서

1. 설계도 단원과 수정 목록, 규칙을 읽는다.
2. 유형별로 문제와 정답을 먼저 만든다. 한 문제를 쓸 때마다 **답을 가리고 직접 풀어** 답이 하나인지 본다.
3. 풀이를 쓴다. 객관식은 오답 보기 3개가 왜 틀렸는지 각각 적는다. 한 문장으로 못 적는 보기는 바꾼다.
4. 힌트1 → 힌트2 → `after_hint2` 순서로 쓴다. `after_hint2`에 적을 일이 없으면 힌트2가 너무 많이 말한 것이다.
5. 20문제를 다 쓴 뒤 아래 「스스로 검사」를 문제마다 한다.
6. 자동 검사기를 돌린다.

## 규칙 요약 (상세는 `v2_generation_rules_v2.md`)

1. **답은 하나.** 열린 질문 금지. 「알맞은 것」을 묻는 객관식의 오답은 내용이 틀린 문장이어야 한다(사실이지만 덜 알맞은 문장 금지).
2. **입력 안내는 고정 문구**(규칙 3.1): 수학 `(숫자만)`, 큰 수 단원 `(쉼표 없이 숫자만)`, 단위 단원 `(단위 없이 숫자만)`, 분수 `(숫자만, 예: 3/4)`, 객관식 `(번호만 써 주세요)`, 국어 단답 `(한 낱말로 써 주세요)`, 영어 단답 `(영어 한 단어로 써 주세요)`. `text`의 마지막 줄에 글자 그대로.
3. **힌트 누설 여섯 꼴 금지**(규칙 4.4):
   - 가정형 — 「만의 자리라면 0이 네 개」「안 되면 하나 큰 숫자」
   - 지시형 — 문제 속에서 정답과 같은 숫자·낱말을 가리킴
   - 조각형 — 「만 묶음 4000, 일 묶음 0600」처럼 답의 조각을 모두 줌
   - 소거형 — 오답 보기 셋을 다 지움
   - 이름형 — 「관계언」「독립언」「체언을 꾸미는 수식언」「사람을 가리키는 주격 관계대명사」처럼 묶음 이름·정의가 보기 하나만 가리킴
   - 지목형 — 정답 보기에만 있는 낱말을 부름

   힌트2에는 검사 방법, 판단 기준, **중간 판정 하나**까지만 쓴다. 판정 둘을 함께 주면 이름형이 된다.
4. **수학**: `answer.kind="value"`, 답은 1 이상의 자연수·기약분수·유한소수·대분수. `expr`을 계산하면 value와 같아야 한다. 정답을 그대로 적을 수밖에 없는 유형(□ 넣기, 숫자 카드, 세기)은 `verify: "manual"` + `verify_note`에 대입·전수 확인 내용. □ 유형의 정답은 문제 속 상대 수의 같은 자리 숫자와 달라야 한다. 뛰어 세기는 「○에서 시작해서 △씩 n번 뛰어 센 수」.
5. **객관식**: `kind="choice"`, value는 ①~④, accepted = `[기호, 숫자, "n번", 보기 문구]`. 정답 위치는 단원 안에서 고르게. 기호 ①~④는 보기 목록에만 쓰고 문장 속 낱말은 작은따옴표로.
6. **단답**: `kind="text"`, 한 낱말. 바른 표기를 모두 accepted에. 영어 관계사 단답은 후보 10개(who·whom·which·that·whose·what·where·when·why·how)를 다 넣어 보고 하나만 맞는지 `verify_note`에 적는다. that도 맞는 자리는 단답 금지.
7. **forbidden**(규칙 7절): 수학은 정답 값과 쉼표·만억·한글 읽기 표기. 객관식은 **정답 기호 하나만** — 품사 이름·who 같은 개념어와 보기 문구를 넣지 않는다. 단답은 정답 낱말 단독.
8. **난이도는 걸음 수**(규칙 6절): easy 1걸음, medium 2걸음 또는 함정 하나, hard 3걸음 이상 또는 조건 둘. 외우면 풀리는 문항은 hard가 아니다.
9. **국어 품사**: 사전에 품사가 둘 이상인 낱말(밝다·크다·붉다·헌·오늘·첫째 등, 규칙 8.1)은 통용 유형에서만 쓴다.
10. **문체**: 문제·힌트·풀이 모두 해요체. 반말·「~다」체 금지.
11. 지문·예문은 전부 새로 쓴다. `out_of_scope` 개념은 풀이에도 쓰지 않는다. 그림 없이 글만으로 풀려야 한다.
12. 한 단원 안에서 같은 수·낱말·문장 틀·힌트 문장을 되풀이하지 않는다.
13. `targets_misconception`은 설계도 문장 그대로이고, 그 오개념을 가진 아이가 실제로 틀리게 되는 문제여야 한다.
14. `review`는 `none`/`needs_review`뿐. 단원 전체 사유는 문항에 되풀이하지 않고 최종 답에 한 번 적는다.

## 스스로 검사 (문제마다, 자동 검사기가 못 잡는 것)

- [ ] 답을 가리고 풀었을 때 같은 답이 나온다. 다른 보기·다른 낱말은 맞지 않는다.
- [ ] 문제 문장을 가리고 **힌트2와 보기만** 읽었을 때 답을 고를 수 없다.
- [ ] `after_hint2`에 적은 일이 「용어를 낱말로 바꾸기」「이어 붙이기」가 아닌 판단·계산이다.
- [ ] 힌트에 「~라면」「안 되면」이 없거나, 있다면 이 문제와 다른 경우의 예다.
- [ ] 힌트가 사실이다(오개념을 부추기는 말, 실제로 있는 다른 낱말로 하는 검사가 없다).
- [ ] 수학 한 자리 답: 정답 숫자가 문제 속 수의 같은 자리 숫자와 다르고, 힌트에 그 숫자가 홀로 나오지 않는다.
- [ ] 겨냥한 오개념으로 풀면 실제로 오답(객관식이면 보기 중 하나)이 나온다.
- [ ] 난이도가 걸음 수 기준과 맞는다.
- [ ] 마지막 줄이 고정 안내 문구다. 보기 한 줄이 폰에서 두 줄을 넘지 않는다.

## 끝내기 전에 (필수)

```
python3 -I tools/check_bank.py bank/problems/<unit_id>.json --blueprint bank/v2_blueprint_<subject>.json
```

(scratchpad 폴더에서 실행.) **FAIL 0**이 될 때까지 고친다. WARN은 고치거나, 안 고치는 이유를 최종 답에 적는다. 자동 검사 통과는 최소 조건이다 — 시범 60문제는 FAIL 0 · WARN 0이었지만 38문제를 고쳐야 했다. 저장소(코드·`seed/`)와 설계도 파일은 고치지 않는다.

## 최종 답

파일 경로, 검사 결과 마지막 줄(총 n문제 · FAIL · WARN), 남은 WARN과 이유, `needs_review` 문항 id와 사유, 단원 전체에 걸리는 확인 대기 사유(한 번만), 설계도·규칙대로 만들기 어려웠던 점. 한국어.
