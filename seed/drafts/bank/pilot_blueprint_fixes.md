# 설계도 수정 목록 (시범 60문제 검토에서 나온 것)

설계도 파일(`v2_blueprint_*.json`)은 고치지 않았다. 아래를 반영해 설계도를 고치거나, 고치기 전에는 생성 에이전트가 이 파일을 설계도보다 먼저 따른다. 근거는 `pilot_review.md`.

## 모든 단원 공통

| 대상 | 수정 |
|---|---|
| 수학 19단원 `answer_rules` 첫 줄 「모든 문제 끝에 (숫자만 써 주세요)」 | 규칙 v2 3.1의 고정 문구 표로 바꿈: 기본 `(숫자만)`, `thousands_comma` 단원 `(쉼표 없이 숫자만)`, `unit_suffix` 단원 `(단위 없이 숫자만)`, 분수 `(숫자만, 예: 3/4)`. 한 단원 안에 문구가 둘 적혀 있는 충돌(큰 수 단원)을 없앰 |
| 수학 `answer_rules` 「정답은 0 이상의 수」 | 「1 이상」으로. 검사기가 0을 FAIL로 보고, 0은 누설 검사에서 「0을 채워요」 같은 말과 겹친다 |
| 수학: `expr`로 계산할 수 없는 유형(□ 넣기, 숫자 카드, 개수 세기, 조건 찾기, 번호 고르기) | 유형마다 `"verify": "manual"` 칸을 넣어 생성 에이전트가 알 수 있게 함 |
| 모든 단원 `misconceptions` | 문항의 `targets_misconception`이 이 문장을 글자 그대로 쓰므로 괄호 예시를 포함해 한 줄로 확정. 유형마다 겨냥할 오개념이 하나 이상 있는지 확인(없으면 추가) |
| 난이도 hard인 유형 | 규칙 v2 6절(3걸음 이상 또는 조건 둘)에 맞는지 다시 봄. 「분류표 짝 고르기」「0이 든 카드로 가장 작은 수」처럼 외우거나 함정 하나로 풀리는 유형은 medium으로 내리거나 조건을 더함. `difficulty_mix`도 같이 고침 |
| 국어·영어 객관식 단원 | 입력 안내를 `(번호만 써 주세요)`로, 단답은 `(한 낱말로 써 주세요)` / `(영어 한 단어로 써 주세요)`로 notes에 적음 |
| 국어·영어 notes의 forbidden 지침 | 「객관식은 정답 기호만, 단답은 정답 낱말 단독」(규칙 v2 7절)으로 바꿈. 영어의 「선행사 + 관계사 조합」 지침은 서버가 forbidden을 읽게 된 뒤에도 필요 없다(객관식은 기호, 단답은 낱말) |

## 다른 단원에도 미리 적용할 점 (같은 문제가 날 곳)

- **수학에서 답이 한 자리이거나 `expr`이 정답 그대로인 유형** 전부: `verify: "manual"`, 한 자리 답은 문제 속 숫자와 겹치지 않게.
- **국어 맞춤법·발음·낱말 관계 단원**: 사전에 표기·뜻이 둘 이상 인정되는 낱말을 피하는 금지 목록을 단원 notes에(품사 통용과 같은 종류의 위험).
- **영어 단답이 있는 단원 전부**(연결어·시제·준동사 등): 「정답이 하나뿐인 자리만」과 후보 대입표를 유형 설명에.
- **분류표·용어 짝짓기 유형**: hard로 두지 않음.
