# 문제 은행 v3 — 빈 학년 14단원 (성호 11-14 「더 늘리고」「국어도」)

지금 앱에 있는 단원은 초4 수학 큰 수, 초5~6 분수(시드), 중2 국어 품사, 고1 영어 관계사뿐이다. 그래서 다른 학년으로 가입한 아이는 분수 문제를 받는다. 이번에는 **빈 학년 7개(초1·초2·초3·중1·중3·고2·고3)에 수학 1단원, 국어 1단원**씩을 만든다. 만드는 방법은 v2와 같다.

## 따를 문서 (경로 기준: 작업 사본 `seed/drafts/`)
1. `bank/gen_prompt_v2.md` — 출력 칸, 만드는 순서, 스스로 검사, 최종 답 형식. **전부 따른다.**
2. `bank/v2_generation_rules_v2.md` — 공통 규칙. 설계도와 다르면 이 규칙이 이긴다.
3. `bank/pilot_review.md` — 나쁜 힌트와 고친 힌트 예.
4. 설계도 형식 예: `bank/v2_blueprint_math.json`, `bank/v2_blueprint_korean.json`의 단원 하나.

## 이번에만 다른 점
- **설계도도 직접 쓴다.** 맡은 단원의 설계도를 `bank/v3_blueprints/<unit_id>.json`에 쓴다. 형식은 v2 설계도와 같고, 단원 1개짜리 배열이다. 성취기준 코드가 확실하지 않으면 `"verified": "미확인"`을 쓰고 코드는 추정이라고 적는다. 코드를 지어내 확인된 것처럼 쓰지 않는다. 근거로 `../../docs/curriculum_bank_research_v0.2.md`(저장소 루트 docs)를 본다.
- **난이도 배분은 easy 6 · medium 10 · hard 4**, 20문제다. 앱이 아이가 고른 난이도(초급=easy, 중급=medium, 고급=hard)로 문제를 낸다. 그래서 단계마다 4문제 이상 있어야 하고, 난이도는 규칙 6절의 걸음 수 기준을 정확히 지킨다.
- 출력: `bank/problems_v2/<unit_id>.json`. 폴더 이름은 v2지만 규칙 v2를 따른다는 뜻이다. 서버가 이 폴더를 적재한다.
- `generator`: `"claude-opus-5-5"`.
- 수학 답은 1 이상의 자연수, 기약분수, 유한소수만 쓴다(채점기가 음수·근호·식을 못 읽는다). 음수나 무리수가 나오는 단원은 「큰 근」「두 근의 곱」처럼 답이 양수 하나가 되게 묻는다.
- 학년이 낮을수록 문장을 짧게 쓴다. 초1·초2는 한 문장 15자 안팎, 문제 글 3줄 이하로 한다.
- 고3 단원은 **2015 개정**, 중3 단원도 **2015 개정**이다(조사 문서 표). 나머지는 2022 개정이다.

## 검사 (끝내기 전 필수)
```
python3 -I tools/check_bank.py bank/problems_v2/<unit_id>.json --blueprint bank/v3_blueprints/<unit_id>.json
```
(`seed/drafts/`에서 실행.) **FAIL 0**이 될 때까지 고친다. 그다음 **두 번째 자체 검토**를 한다. 20문제 각각을 답을 가린 채 처음부터 다시 풀고, 힌트2와 보기만으로 답이 나오는지 다시 본다. 고친 것은 최종 답에 적는다.

## 하지 않는 것
- 자기 단원의 두 파일(설계도 1개, 문제 1개) 밖은 고치지 않는다. 코드, `seed/seed_v0.1.json`, 다른 단원, 도구가 다 해당한다.
- git commit·push 하지 않는다. LLM API를 부르지 않는다.
- `.env`를 열지 않는다.
- 실존 작품, 교과서·기출 문장, 실명, 상표를 쓰지 않는다.
